# 秋招手记

一个记录秋招投递进度的小工具：一行一条投递，状态直接在表格里改，展开能看到每家公司完整的流程时间轴，还有投递节奏、阶段转化、渠道和城市分布等统计。

- **数据只存在你自己的设备上**：Mac 应用存在本机，网页版存在当前浏览器里，不上传到任何服务器，也没有账号。
- 支持 Mac 应用和网页版两种用法，功能相同，但**两边数据不互通**（可以用备份文件搬过去）。

---

## 安装

### 方式一：Mac 应用（推荐）

适用于 macOS 13 及以上。

1. 到本仓库的 [Releases](../../releases/latest) 页面下载最新的 `QiuzhaoNotes_x.y.z_*.dmg`。
   文件名是 `universal` 的同时支持 Apple 芯片和 Intel 芯片；`aarch64` 只支持 Apple 芯片（点左上角  →「关于本机」，「芯片」写着 Apple M 系列就是）。
2. 双击打开 dmg，把「秋招手记」拖进「应用程序」文件夹。
3. **第一次打开**：应用没有经过 Apple 公证，直接双击会提示“无法验证开发者”。按下面任意一种方式打开一次即可，之后就能正常双击：
   - 在「应用程序」里**右键点「秋招手记」→ 打开 → 再点「打开」**；或
   - 打开「系统设置 → 隐私与安全性」，在下方找到秋招手记的提示，点「仍要打开」。

   如果提示“已损坏，无法打开”，在「终端」里运行下面这行后再打开：

   ```bash
   xattr -cr /Applications/秋招手记.app
   ```

**更新**：有新版本时，应用启动几秒后右下角会提示「发现新版本」，点「更新并重启」就会自动下载、安装并重新打开；也可以在「数据与设置 → 关于与更新」里手动检查。你也可以随时下载新的 dmg 覆盖安装。

不论哪种方式，**数据都不会丢**：数据保存在应用之外的独立目录里，更新只替换应用本身。

### 方式二：网页版

如果有人已经部署好了网页版，直接用浏览器（Chrome、Edge、Safari 均可）打开链接就能用，不需要安装。

注意：网页版的数据保存在**当前这个浏览器**里。换浏览器、换电脑、用无痕模式，或清除网站数据，都看不到之前的记录。请定期在「数据与设置」里导出备份。

想自己部署一份网页版，见下文 [自己部署网页版](#自己部署网页版)。

## 使用

### 1. 创建招聘季

第一次打开先到左侧 **数据与设置 → 我的招聘季**，填名称（如“2026 秋招”）、起止日期和投递目标，点「创建并设为当前」。

之后随时可以点招聘季旁的「编辑」修改目标和日期，也可以点左下角目标卡片里的「修改目标」直接跳过去。归档的招聘季会收在「已归档的招聘季」里，随时可以恢复。

### 2. 新增投递

点右上角「新增投递」（Mac 上也可以按 ⌘N），填写：

- 公司、岗位（必填），渠道（官网、内推等），城市（可以填多个，回车或逗号分隔）
- 当前状态和投递日期：默认“已投递、今天”，还没投的选“待投递”
- **投递进度链接**：官网“我的投递 / 个人中心”的状态页，以后一点就能去看进度
- 岗位 JD 链接、备注（可选）

### 3. 在进度看板里更新状态

**进度看板** 是主要的工作页面：

- 每行“状态”一栏是下拉框，收到新进展时直接选新状态即可（例如 筛选中 → 笔试 → 一面）。
- 点这一行的任意位置（或行首的 ›）展开，能看到这家公司的完整流程时间轴。点任一节点可以「在此之前补录」漏记的进展、「纠错」记错的那一条，或者「删除这条」。
- 投递日期、工作地点、备注都可以直接点开修改：地点是一个个城市标签，回车添加，输入框为空时再按回车（或点「保存」、点别处）保存，Esc 取消。
- 顶部的卡片显示总投递、流程中、已挂掉等数量；下面的标签按环节筛选（所有一面相关的状态都归在“一面”下），还能按结果、城市、渠道筛选和排序。
- 删除一条投递后，页面底部的提示里可以立即「撤销」。

在「数据总览」的「近期日程」里，已逾期的待办排在最前。点一条日程可以查看类型、投递和备注，点「完成」直接标记完成（提示里可以撤销）；要改时间、取消或删除，点「打开这条投递」。

### 4. 查看统计

**深度分析** 页显示：

- 累计投递、流程中、进入人工面试、拿到 Offer 的岗位数
- 各环节的触达人数和比例
- 最近 12 周的投递热力图和每周投递量（鼠标移上去能看到日期和数量）
- 各渠道的投递数和面试、Offer 转化率
- 城市分布

可以切换招聘季，或只看某段日期内的投递。

### 5. 自定义状态与环节

**数据与设置 → 管理状态与环节**：每个环节（简历筛选、笔试、一面……）下面列着它的状态。

- 给环节改名时，它下面的状态名会一起改。
- 新增环节时勾选「同时创建常用状态」，会自动生成“待X / X中 / X待结果 / X通过 / X挂”。
- 点任意状态可以改名、换颜色或归档；归档的内容在页面底部可以恢复。

渠道（官网、内推、招聘平台……）在 **数据与设置 → 投递渠道** 里新增和修改。

### 6. 备份、恢复和换电脑

所有数据只在本机，**建议隔一段时间导出一次备份**：

- **导出**：数据与设置 →「导出完整备份」，得到一个 `.json` 文件（Mac 上也可以按 ⌘⇧E）。
- **恢复 / 换设备**：在新设备上打开 数据与设置 →「选择备份并预览」，确认内容无误后点「确认整体恢复」。Mac 应用和网页版之间也可以这样互相搬数据。
- 每次整体恢复或导入之前，应用会自动保留一份“恢复副本”（保留最近 5 份），恢复错了可以在「本机恢复副本」里退回去。

### 7. 从旧表格导入（可选）

在 **投递管理 →「导入原始 JSON」** 可以导入其他工具导出的投递列表。文件是一个 JSON 数组，每条记录包含：

| 字段 | 说明 |
| --- | --- |
| `id` | 记录的唯一编号 |
| `company`、`position`、`location`、`channel` | 公司、岗位、城市、渠道（渠道必填，需与应用里的渠道同名） |
| `link` | 投递进度链接（状态页） |
| `applyDate` | 投递日期，如 `2026-09-01` |
| `status` | `待投递`、`已投递`、`筛选中`、`笔试`、`测评中`、`一面`、`二面`、`三面`、`四面`、`五面`、`泡池`、`Offer`、`挂掉` 之一 |
| `createdAt`、`updatedAt`、`statusUpdatedAt` | 时间戳，如 `2026-09-01T09:00:00+08:00` |

导入前会先显示预览，确认后才写入：新记录会被添加，之前导入过的记录只更新状态，和已有投递重复的会跳过，不会删除任何现有数据。

### Mac 快捷键

| 快捷键 | 作用 |
| --- | --- |
| ⌘N | 新增投递 |
| ⌘F | 搜索当前页（没有搜索框的页面会跳到进度看板） |
| ⌘⇧E | 导出备份 |
| ⌘, | 打开设置 |
| 文件 → 恢复备份… | 选择备份文件并预览 |

## 常见问题

**数据存在哪里？**
Mac 应用：`~/Library/Application Support/com.autumnnotes.desktop.dev/autumn-notes.sqlite`。删除应用本身不会删掉这个文件。
网页版：当前浏览器的网站数据（IndexedDB）里。

**为什么网页版和 Mac 应用里的数据不一样？**
两者各自独立保存。要同步，请在一边导出备份，在另一边恢复。

**累计投递和记录总数不一样？**
“待投递”的草稿不算投递，所以统计里的“已投递”可能比记录总数少几条。

## 自己构建和部署

需要 [Node.js](https://nodejs.org/) 22.12 或以上。

```bash
npm ci
```

### 本地运行网页版

```bash
npm run dev
```

打开终端里显示的地址（默认 `http://localhost:5173`）。

### 自己部署网页版

```bash
npm run build
```

把生成的 `web-dist/` 目录发布到任意静态托管服务。应用使用前端路由，需要把所有找不到的路径都回退到 `index.html`：

- **Cloudflare Pages**：构建命令 `npm run build`，输出目录 `web-dist`，无需额外配置。
- **Vercel / Netlify**：构建命令和输出目录同上，并添加“所有路径重写到 `/index.html`”的规则。
- **Nginx**：参考 [`deploy/nginx/autumn-notes.conf`](deploy/nginx/autumn-notes.conf)。

目前只支持部署在域名根路径（如 `https://notes.example.com/`），不支持 `https://example.com/autumn-notes/` 这样的子路径（因此 GitHub Pages 的项目页面不能直接使用）。

### 打包 Mac 应用

额外需要 [Rust](https://rustup.rs/) 和 Xcode 命令行工具（`xcode-select --install`）。

```bash
npm run build:mac:dmg
```

生成的安装包在 `src-tauri/target/release/bundle/dmg/`。

### 发布新版本（维护者）

应用内更新依赖 GitHub Releases 上的签名文件，发布步骤：

1. 把 `package.json` 和 `src-tauri/tauri.conf.json` 里的 `version` 改成新的版本号（如 `0.2.0`），提交并合并到 `main`。
2. 运行：

   ```bash
   npm run release -- --notes "这次更新了什么" --publish
   ```

   脚本会打包、用更新签名密钥签名、生成 `latest.json`，并创建 `v0.2.0` 的 Release。已安装的应用下次启动就会提示更新。

- 更新签名密钥在 `~/.tauri/qiuzhao-notes.key`，**不要提交到仓库，并请另外备份**。密钥丢了的话，已安装的应用无法自动更新到之后用新密钥签名的版本，只能手动下载安装一次。
- 安装了 Intel 目标（`rustup target add x86_64-apple-darwin`）时，脚本会打出同时支持两种芯片的 universal 版本。

> 不要修改 `src-tauri/tauri.conf.json` 里的 `identifier`，否则应用会找不到之前保存的数据。

### 运行测试

```bash
npm run typecheck
npm run test:sheet-model        # 单个领域测试，其余见 package.json 的 test:* 脚本
npx playwright install chromium
npm run test:v2-app             # 浏览器集成测试
npm run test:mac                # Rust / SQLite 测试（需要 Rust）
```

### 目录结构

| 路径 | 内容 |
| --- | --- |
| `src/domain/` | 数据模型、状态规则、统计计算（不依赖界面） |
| `src/repositories/` | 读写命令，以及 IndexedDB / SQLite 存储接口 |
| `src/features/` | 各页面：投递管理、进度看板、深度分析、设置 |
| `src/platform/` | 网页版与 Mac 应用的差异（文件读写、菜单等） |
| `src-tauri/` | Mac 应用外壳（Tauri 2 + SQLite） |
| `tests/` | 单元测试与 Playwright 浏览器测试 |
| `docs/`、`plan.md` | 开发过程中的设计与验收记录 |
