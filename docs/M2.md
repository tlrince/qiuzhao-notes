# M2 数据层与业务命令

状态：核心模块完成，独立验收日期：2026-09-17。

M2a 提供 `createSnapshotRepositories(store)`，把 M0 领域命令编排为统一的 `read → 校验/规则 → CAS commit` 事务。应用、日程、招聘季和设置都通过同一快照存储，`expectedUpdatedAt` 与全库 `revision` 同时保护并发编辑；失败不会提交部分数据，成功提交后触发 RepositoryEvents。

M2b 提供 `createIndexedDbSnapshotStore()`。默认数据库为 `autumn-notes-v1`，包含 `snapshot` 与 `meta` 仓库，单个 readwrite 事务内检查 revision 并写入，支持关闭、迁移、BroadcastChannel 通知和 25MB 以外数据的上层备份限制。写入等待事务 `oncomplete`，不会把尚未提交的请求当作成功。

M2c 提供 `src/repositories/desktop/sqlite.ts` 与 Rust SQLite 核心。Tauri 命令在应用数据目录使用 SQLite、schema migration、revision CAS 和单事务写入；桌面适配器只动态调用 IPC。规范化业务表已建立外键/级联约束，当前快照作为跨端交换的权威 JSON 保存，后续业务量增大时可在同一事务中填充规范化索引。

独立验收：M2 TypeScript 测试 7/7；M2 平台 CAS 测试 8/8；Rust SQLite/平台测试 5/5；`npm run typecheck` 通过。Web IndexedDB 使用 fake-indexeddb 覆盖首次读取、重开恢复、深拷贝、冲突与关闭；共用仓库覆盖事务通知、失败不变、日程和招聘季。

本记录写成时页面集成尚未开始；之后 R2 与 M3 v2 已把 IndexedDB/SQLite 快照接入当前应用页面。当前原始 JSON 导入使用单独的状态映射与招聘季原子替换命令，不绕过校验。真实导出文件可以完整解析，导入仍由用户在应用中预览并确认，不由开发过程自动改写现有数据库。
