# R3 表格投影验收

状态：已完成。R3 在 R1 的 v2 事件链投影之上增加纯函数表格投影；随后由 R4/M4b 接入 v2 Repository 与进度表页面。

## 投影内容

- 默认列只由所给投递中的有效环节事件、有效跳过注记与用户固定列组成；按定义 sortOrder 排列，筛选不会改变列集合。直接跳到二面不会补出一面。
- 单元格按稳定 stageId 聚合 visit。visit 内多个 phase 只计一次；再次筛选、泡池子或重面保留为独立记录，并同时输出进入日、最近更新日、实际触达日、最新状态和完整 visit 事件。
- 当前停留从当前 visit 首日算到工作空间业务日期；离开后的最近 visit 到下一有效事件日结束。同日间隔可为 0 天。涉及迁移不确定连接的时间间隔返回 null，并标记 needs_confirmation。
- 当前状态取应用与有效链尾的一致投影。当前状态筛选与有效历史筛选分离；作废事件不会出现在单元格或历史筛选中。当前失败环节、历史曾失败、Offer 拒绝分别投影。
- 只有实际阶段事件输出 actualOn；面试等待状态、纯失败结论、未来 Schedule 不会被显示成实际面试。待办日程作为独立字段按 startsAt 排序。
- Offer 只按收到 Offer 的事件计数；接受/拒绝事件附着到唯一未决 Offer。若存在多笔未决 Offer，事件模型缺少 offerId，相关 receipt 标记 needs_confirmation，不猜测决定归属。
- 投影会校验 Application currentStage / appliedOn 与 ProgressRecord 链尾及投递日期一致，不修改输入对象，也不读写存储。

## 独立验收

- `npm run test:r3`：15 项纯函数测试全部通过。
- `npm run build:domain` 与生产 `npm run build` 通过。
- 覆盖空 draft、动态列、直接跳级、重复 visit、实际日期与停留、当前/历史过滤、失败归因、Offer、计划日程、作废历史、不确定迁移边、输入不可变和状态/日期不一致负例。

## 后续边界

R3 只输出表格数据模型，不包含 React 单元格编辑、键盘导航、列宽/顺序保存或 v2 持久化接入；这些留给 R4/M3 v2 集成。
