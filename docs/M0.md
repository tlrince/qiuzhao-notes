## 冻结的规则与补充约定

1. 新建默认是 active 草稿；非草稿必须填写 appliedOn。新建后期阶段仅记录 submitted 与所选阶段，stageOccurredOn 缺省为 appliedOn。
2. 草稿可跳至任意后续阶段，此命令的 occurredOn 同时作为投递日期。普通推进只允许前进，已结束流程先重新开启；同阶段/同结果命令不新增事件。
3. 阶段事件日期不得早于投递日期；普通推进日期不得早于上一个有效阶段日期。结果日期不得早于投递日期或上一有效结果日期。
4. 草稿可以主动结束或淘汰，但不能获得 Offer。重新开启记录 active 结果事件。结束流程保留当前阶段，主动结束保留此前 Offer 记录。
5. 所有历史按逻辑顺序保存；纠错将旧事件标记 supersededAt，在原位置后插入替代记录，后续事件保持原顺序。当前状态取最后一个有效事件，而非按 createdAt 排序。恢复备份必须保留数组顺序。
6. 删除当前阶段事件可恢复到前一有效阶段；删除唯一 submitted 可恢复草稿。仍有其他有效阶段时不能删除 submitted。纠错不得再次修改已失效事件。历史跨层回退可从最新事件逐项纠正。
7. 编辑 appliedOn 同步纠正 submitted 事件，保留原记录。若新日期晚于其他有效阶段或结果日期，整体失败。
8. Update/Transition/CorrectHistory 必须提供 expectedUpdatedAt，不匹配返回 CONFLICT。Mock 保证每次实际编辑的 updatedAt 单调增加；M2 应在真实事务中完成检查与写入。
9. 查询日期范围两端包含，按 appliedOn 筛选并排除草稿；空数组表示不限制。公司/岗位关键词忽略大小写。默认 updatedAt 降序，ID 作为稳定次排序；appliedOn 为空始终置后。查询不隐式使用当前招聘季，必须传 seasonId。
10. 完成或取消日程不会改变岗位阶段。删除岗位移除全部关联事件和日程。日程用 UTC 时间排序；业务日日期不进行 UTC 转换。
11. 变更订阅在成功提交后触发；监听器失败会记录错误，不反向影响已经成功的命令。Mock 不提供跨标签广播。
12. 第一条招聘季自动成为当前招聘季；允许查看归档季，无招聘季删除接口。工作空间初始无招聘季与岗位，仅有默认渠道。
13. AnalyticsResult 的比率是 0–1 的数或 null（分母为零）；格式化为百分比由 UI 处理。热力图窗口与日期单元通过输出协议提供；M5 负责计算。投递目标由完整招聘季统计，不复用分析页受筛选的计数。
14. 校验器接受带类型的领域数据；unknown JSON 的结构校验由 M8 的 BackupService.validate 负责，禁止直接将导入文件断言为 DataSnapshot。

## Mock 独立使用

```ts
import { createMemoryRepositories } from '../src/repositories/memory.js';
import { acceptanceSnapshot } from '../src/fixtures/acceptance.js';

const mock = createMemoryRepositories(acceptanceSnapshot());
const applications = await mock.applications.list({ seasonId: '2026-autumn' });
const unsubscribe = mock.events.subscribe(change => console.log(change));
const detail = await mock.applications.getDetail('B');
if (detail) {
  await mock.applications.transition({
    id: 'B', expectedUpdatedAt: detail.application.updatedAt,
    kind: 'stage', stage: 'interview_1', occurredOn: '2026-09-16',
  });
}
unsubscribe();
```

无参数创建 Mock 得到空工作空间。`snapshot()` 和 Repository 返回值均为深拷贝，不能通过修改返回值绕过命令。可注入 now/id 生成器以实现确定性测试。
