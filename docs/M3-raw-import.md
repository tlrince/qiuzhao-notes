# M3 原始投递 JSON 状态导入验收

## 状态解析

解析器只接受显式支持的中文状态；未知状态、缺失渠道、重复源 ID、无效时间或无法建立可信顺序时，预览报告错误并阻止整批写入。

| 原始状态 | v2 当前状态 | 导入历史 |
| --- | --- | --- |
| 待投递 | 待投递草稿 | 不伪造状态事件；原日期保存在导入备注 |
| 已投递 | 已投递 | 一条实际提交事件 |
| 筛选中 | 筛选中 | 已投递 → 筛选中 |
| 笔试 | 笔试中 | 已投递 → 笔试中 |
| 测评中 | 测评中 | 已投递 → 测评中 |
| 一面 | 一面中 | 已投递 → 一面中 |
| 挂掉 | 挂掉（环节未知） | 已投递 → 挂掉；不猜测失败环节 |

公司、岗位、城市、渠道、职位链接、备注、关注标记、时间和源记录 ID 会映射到 v2 字段或备注。非 HTTP(S) 的原链接文字作为普通备注保留，不会被渲染成可执行链接。

## 原子导入流程

投递页选择原始 JSON 后，先显示总数、各状态数量和记录问题。校验有任何问题时，不允许部分导入。确认后只替换选定招聘季内的投递、进度和关联日程，其他招聘季与工作空间配置保留；被替换的完整工作空间快照由存储层原子留存。标准 v1/v2 备份仍通过设置页的备份恢复入口处理。

## 验证

- 一份真实导出文件的只读解析：全部记录有效、0 条问题，覆盖上表所有状态。
- `npm run test:raw-import-v2`：8 项解析与快照校验通过。
- `npm run test:m3import`：6 项原子替换命令测试通过，包含跨季隔离、恢复副本、重复 ID、无效事件和 CAS 冲突。
- `npm run test:v2-app`：浏览器中先创建旧记录，再预览并替换为带有筛选中、挂掉和待投递状态的样例；刷新后状态仍保持，测试通过。

此验收只验证导入功能与用户文件的只读解析结果；没有自动重写或替换用户当前设备中的真实业务数据库。用户需要在目标应用的投递页主动选择原始 JSON 并确认替换目标招聘季。
